# 室内巡逻机器人系统需求文档

## 1. 概述

### 1.1 项目目标

开发一个能在 Gazebo Fortress 仿真环境中运行的室内巡逻机器人系统。机器人按照预设固定路线自动巡逻，具备低电回充、异常检测报警、日志记录等完整巡检能力。

### 1.2 适用范围

本文档为功能需求规格书，包含功能需求与技术约束，不涉及模块划分、架构设计和实现方案。

### 1.3 术语

| 术语       | 说明                                 |
| ---------- | ------------------------------------ |
| 巡逻路线   | 由多个有序巡逻点组成的巡检路径       |
| 巡逻点     | 路线上机器人的目标停留坐标           |
| 充电桩     | 机器人自动回充的目标位置             |
| 低电阈值   | 触发回充行为的电量临界值             |
| 行为树(BT) | BehaviorTree.CPP，用于顶层任务编排   |

## 2. 功能需求

### 2.1 巡逻任务管理

#### FR-01 巡逻路线的定义与加载

- 巡逻路线及其巡逻点定义在 YAML 配置文件中，修改 YAML 文件即可调整路线，无需修改代码。
- 每条路线包含：路线名称、路线优先级（排序依据）、巡逻点列表。
- 每个巡逻点包含：地图坐标(x,y)、朝向(yaw)、停留时长（秒）、可选异常模拟字段。
- 充电桩坐标在同一个 YAML 文件中定义。
- 系统不硬编码路线或巡逻点数量上限。

#### FR-02 巡逻点到达行为

- 机器人导航到达巡逻点后，按配置的停留时长原地停留，模拟观察检查。
- 停留期间通过摄像头拍照存档。
- 停留结束后自动前往下一个巡逻点。

#### FR-03 路线执行顺序

- 多条路线按 YAML 配置中的顺序依次循环执行。
- 路线 1 → 路线 2 → … → 路线 N → 路线 1 → …，循环往复。

#### FR-04 巡逻执行模式

- 系统启动后进入循环巡逻模式，永不停歇地按顺序执行所有路线。
- 只有在电量低于阈值、或收到系统控制指令时（见 FR-10），才会中断循环。

---

### 2.2 电池管理与自动回充

#### FR-05 电量模拟

- 系统模拟电池电量，从满电开始消耗。
- 巡逻过程中持续消耗电量（行进消耗 + 停留消耗）。
- 回充过程中电量逐渐恢复。

#### FR-06 低电自动回充

- 巡逻过程中电量低于配置的低电阈值时，立即中断当前巡逻任务，自动导航至充电桩。
- 保存中断状态（当前执行的路线编号、已完成的最后一个巡逻点编号）。

#### FR-07 充电完成后的恢复

- 电量恢复到满电（或配置的恢复阈值）后，自动离开充电桩，从上次中断的下一个未完成巡逻点继续巡逻，而不是重新从头开始。

---

### 2.3 异常检测与报警

#### FR-08 环境异常模拟

- YAML 配置中的巡逻点可预设模拟异常（如 `temperature_high`、`smoke_detected`）。
- 机器人到达该巡逻点时触发相应报警。

#### FR-09 系统状态异常监控

- 持续监控机器人自身状态：导航失败、传感器离线等。
- 发生状态异常时自动报警。

#### FR-10 报警严重性分级与响应

- 异常类型附加严重性级别：`warning` 或 `critical`。
- `warning` 级别：记录报警日志，不中断巡逻，继续前往下一个巡逻点。
- `critical` 级别：记录报警日志，立即终止当前巡逻路线，等待操作者指令。

---

### 2.4 系统控制

#### FR-11 启停控制

- 通过命令行/终端 ROS2 Service 发送控制指令：
  - `start_patrol`：启动巡逻
  - `pause_patrol`：暂停巡逻（停在原地）
  - `resume_patrol`：恢复巡逻
  - `stop_patrol`：停止巡逻（终止任务）

---

### 2.5 日志记录

#### FR-12 日志内容

- 关键事件：巡逻开始/结束、异常报警、低电回充、充电完成。
- 巡逻过程：每个巡逻点的到达时间、停留时长、离开时间。
- 异常详情：异常类型、触发位置、严重性级别。

#### FR-13 日志输出

- 运行时同步输出至终端控制台。
- 同时写入日志文件，按日期/任务轮次组织，持久保存以供事后审计回溯。

---

### 2.6 动态障碍物处理

#### FR-14 自动绕行

- 巡逻导航过程中遇到动态障碍物时，由 Nav2 局部规划器自动尝试绕行。

#### FR-15 超时跳过

- 若障碍物持续存在导致无法到达巡逻点，超过配置的超时时间后，机器人放弃当前巡逻点，记录超时告警，继续前往下一个巡逻点。

---

### 2.7 视觉巡检

#### FR-16 巡逻点拍照

- 到达每个巡逻点后通过摄像头拍摄一张照片，保存至指定目录。
- 文件名包含路线编号、巡逻点编号和时间戳，便于事后对照。

## 3. 技术约束

### 3.1 技术栈

| 组件           | 版本/选型                   |
| -------------- | --------------------------- |
| 操作系统       | Ubuntu 22.04                |
| ROS2           | Humble                      |
| 行为树         | BehaviorTree.CPP v4         |
| 仿真引擎       | Gazebo Fortress (Ignition)  |
| 导航框架       | Nav2 (Navigation2)          |
| 容器化         | Docker                      |

### 3.2 机器人模型

- 使用开源差分驱动机器人模型（TurtleBot3）。
- 底盘为差分驱动，满足巡逻导航需求。

### 3.3 传感器配置

- **激光雷达 (LiDAR)**：用于地图定位和导航避障。
- **摄像头 (Camera)**：用于巡逻点拍照存档。
- 不要求 IMU。

### 3.4 仿真环境

- 单层平面室内场景，包含 3-5 个房间和至少一段走廊。
- 场景中包含静态墙壁、固定障碍物，以及至少一条连通各房间的路径。
- 充电桩在场景中有一个固定位置。

### 3.5 地图

- 使用预先建好的地图（Occupancy Grid Map），通过 SLAM 工具一次性建立，巡逻时直接加载。
- 所有巡逻点和充电桩坐标均基于该地图定义。
- 后续可扩展边巡逻边建图（SLAM）的能力。

### 3.6 控制通信

- 启停/暂停/恢复功能通过 ROS2 Service 接口暴露。
- 系统状态和报警信息通过 ROS2 Topic 对外发布。

### 3.7 行为树应用边界

- 关键决策逻辑（路线选择、电量判断、异常分级）使用 BehaviorTree.CPP 编排。
- 底层动作执行（导航到目标、拍照保存）以纯代码形式实现，作为 BT 的叶子节点调用。

---

## 4. 非功能需求

### 4.1 可配置性

- 巡逻路线、巡逻点、充电桩坐标、低电阈值、停留时长、障碍物超时时间等，均通过 YAML 配置文件管理，无需修改代码。

### 4.2 可靠性

- 动态障碍物不导致系统死锁（有超时跳过机制）。
- 电量不足时自动回充，不出现"半路没电"。
- 异常报警不影响非关联路线巡逻（warning 级别不中断任务）。

---

## 5. 后续扩展方向（非本阶段范围）

- 多机器人协同巡逻
- 摄像头图像分析（目标检测、异常识别）
- SLAM 边巡逻边建图
- 按时间段调度不同路线（白天/夜间巡逻计划）
- Web 控制面板 / 手机端远程控制
- 真实场景部署与充电桩视觉精确定位（AprilTag）
